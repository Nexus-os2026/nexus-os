# Mother Nexus broker boundary

This file keeps its historical path for retained foundation references. It is
not an old-product phase plan or a claim that every retained actuator is exposed
to Mother. Current roles and acceptance come from MOTHER.md, Git and the approved
mission. Closed routes stay closed. The old Nexus must never break Mother Nexus.

## Mother and the host

Mother's `EffectPort` is sealed to `GovernedPort`. `mother/host` constructs the
broker and holds its Owner side; Mother receives an Owner-confirmed agent door,
bound to her agent and its opened/adopted runs. Mother cannot construct the
broker, mint grants, impersonate the Owner or use kernel actuators directly.
Consent binds the exact mission hash and request but does not grant effects.

The current native GTK4 status window and Stop ingress do not supply mission,
door or held-mission dialogs: those answers decline. The terminal walk is a
separate deterministic demonstration, not completed native acceptance.

## Commitments and effects

Each available effect uses backend-owned target identity and exact parameter
digests. Its commitment binds agent, run, capability, effect class, grants,
leases, policy generation and deadline. Evidence must be recorded before
commitment/authorization becomes effective. R0 needs its live grant; bounded R1
effects need commitment, revalidation, bounds and evidence; sensitive or
irreversible R2 effects additionally need the Owner's exact one-shot native
approval. Approval values cannot be forged from UI strings or saved JSON.

Immediately before execution, revalidate all bindings and consume the commitment
once. Terminal outcome and cleanup errors remain observable. Credentials reach
a request only through its commitment/origin-bound lease, with identity checked
again. A caller's PID, path or model output never substitutes for retained
authority. An Owner-only synthetic approval probe proves no real effect and
its evidence must remain labelled synthetic.

## Stop, halt and Files

A broken coordinator fences its port and halts its door before recording.
Subsequent admission is refused; a cancellation sweep is a backstop. No
coordinator/port/broker lock is held across the halt's evidence writes. An
executing actuator stops cooperatively at its next check; already performed
effects are not undone. Missing halt history is not permission to continue;
recording failures and owed records stay observable. After restart, a door asks
again; an unclean Mother journal holds unfinished missions for the Owner.

Files adds session provenance, exclusive admission, publication and settlement.
Unknown, interrupted or recovery-required publication never becomes ordinary
approved success or clean lapse. Unacknowledged terminal obligations are retained;
only the correct confirmed settlement releases them. Stop precedes lock/record
waits, but its records may still block or fail. A clean close cannot hide an owed
terminal record. Replay and crash recovery refuse uncertain authority.
The registered [Files oracles](m2d-c-lite-oracles.md) remain unchanged.

## Retained mechanisms are not Mother features

The broker still contains tool, egress, browser, isolated-display perception/input
and credential mechanisms. Their presence is not a Mother route, general process
permission, paired door, voice capability or research integration. Any contact
needs an explicit reviewed mission and the existing security checks. Do not
resurrect deleted app commands or treat an old roadmap as authorization.

Limits of retained mechanisms remain limits: process groups/resource limits are
not an OS filesystem/network sandbox and a workload that leaves its group is not
contained by that group. Browser origin checks and proxy observations are not a
private network namespace. Machine-policy checks assume trusted root; post-launch
observation is detection, not prevention, and initial egress may precede refusal.
The proxy is unauthenticated, checks a plain-HTTP connection's first request,
and relies on the granted address thereafter. Host-interface views do not cover
every possible on-link route. Chrome must honor its flags. Same-user processes
can reach same-user sockets and state. Owner-desktop input/observation and
microphone capture are not authorized Mother routes. No speech, messaging,
remote-device or background-service security is claimed by this document.

Native confirmation is not authenticated secure attention against hostile
same-user desktop clients or synthetic input. Tool descriptor safety depends on
close-on-exec; libraries outside owned secret buffers may retain copies. A
native input interruption can only make a best-effort release, not undo prior
input. These foundations cannot justify a broader Mother security claim.

## Evidence and review

Use the exact build's journal/evidence receipts and tests. An unkeyed chain is
not authenticated memory; in-memory audit is not durable evidence. The
[credential facade note](../architecture/decisions/0004_credential_vault_facade.md)
distinguishes retained legacy storage from broker lease authority. Mother is
Linux-first; no Windows/macOS control or security acceptance is claimed.

See [SECURITY.md](../../SECURITY.md), [THREAT_MODEL.md](../../THREAT_MODEL.md) and
AGENTS.md for permanent fail-closed, containment, error, Git and verification
rules. A source guard is evidence with limits, not a proof of universal mediation.
