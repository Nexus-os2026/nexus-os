## 2. The failure (`baseline/`)

Closure CI run 37191730167 (attempt 1, `workflow_dispatch`, head
`a7001311`) failed only `security-audit-linux`: `cargo audit` reported
`error: 1 vulnerability found!`, RUSTSEC-2026-0327 in wasmtime 43.0.2
(published 2026-10-02, CVSS 9.3). `test-linux`, `test-frontend` and
`test-python` passed.

## 3. Reachability (Phase A, `matrices/reachability.md`)

Production Nexus uses **core Wasm only**:
- no Component Model;
- no async;
- no WASI.

That use is confined to five `nexus-sdk` files. `nexus-protocols` and
`nexus-benchmarks` use Wasmtime only in tests and benches. 25 workspace
packages depend on Wasmtime, the desktop included, and the list is the same
before and after. A core-only build, with Wasmtime's `component-model` and
`async` features compiled out, compiles all three users and passes the SDK's
tests. That is compile evidence that no Nexus code needs those APIs.

## 5. The dependency repair (Phase C, `matrices/lockfile-delta.md`)

The workspace compiled against 36.0.17 with no Nexus source change, so no
API-compatibility repair was made. `Cargo.lock` changed 46 (name, version)
pairs out and 46 in. Every change is the Wasmtime line or caused by it:
- Cranelift 0.130.2 → 0.123.17, with its internals;
- `wasm-compose` and its unmaintained crates removed;
- `toml` 0.8.2 → 0.8.23 and `proc-macro-crate` 2.0.2 → 2.0.0. Wasmtime
  36's cache crate needs `toml` ^0.8.10, which unifies with the workspace's
  0.8 copy. `toml` 0.8.23's `toml_datetime` excludes `proc-macro-crate`
  2.0.2's `=0.6.3` pin.

No other package moved.

## 6. Decision surfaced: the Phase Zero Wasmtime guard (`matrices/guard-change.md`)

`p0_fg_dep_wasmtime_uses_no_dynamic_component_val_api` required `deny.toml`
to hold exactly one RUSTSEC-2026-0316 exception reasoned on "wasmtime
43.0.2". The fresh `cargo deny` proves that exception stale. The security
script fails on stale exceptions, and the mission requires removing it.
Both cannot hold, so the guard was changed, in a file outside the
mission's initial list.

That single assertion now runs the other way: no `deny.toml` exception may
name `wasmtime`, RUSTSEC-2026-0316 or RUSTSEC-2026-0327. Every other
assertion is unchanged:
- the alias, glob, component and rename checks;
- the typed core entry functions;
- the latent-API needles.

One new check rejects Wasmtime's async and component-model entry points
(`call_async`, `instantiate_async`, `func_wrap_async`, `func_new_async`,
`async_support`, `wasm_component_model[_async]`) in production sources that
use Wasmtime. Four mutation controls prove the guard detects each wrong
state (`matrices/controls.md`).

Historical Phase Zero records that describe the 43.0.2 acceptance
(`docs/security/phase0-final-gate-dossier.md`,
`docs/security/phase0-c5-authority-inventory.md`, `docs/qa/`) are left as
written; this directory supersedes them for Wasmtime.
