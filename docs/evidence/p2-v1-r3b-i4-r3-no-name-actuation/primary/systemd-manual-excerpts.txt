  530         Note that many of the methods exist twice: once on the Manager object and once on the respective unit objects.
  531         This is to optimize access times so that methods that belong to unit objects do not have to be called with a
  532         resolved unit path, but can be called with only the unit id, too.
  533
  534         GetUnit() may be used to get the unit object path for a unit name. It takes the unit name and returns the
  535         object path. If a unit has not been loaded yet by this name this method will fail.
  536
  537         GetUnitByPID() may be used to get the unit object path of the unit a process ID belongs to. It takes a UNIX
  538         PID and returns the object path. The PID must refer to an existing system process.  GetUnitByPIDFD() may be
  539         used to query with a Linux PIDFD (see: pidfd_open(2)) instead of a PID, which is safer as UNIX PIDs can be
  540         recycled. The latter method returns the unit id and the invocation id together with the unit object path.

  585         KillUnit() may be used to kill (i.e. send a signal to) all processes of a unit. It takes the unit name, an
  586         enum who and a UNIX signal number to send. The who enum is one of "main", "control" or "all". If "main", only
  587         the main process of the unit is killed. If "control", only the control process of the unit is killed. If
  588         "all", all processes are killed. A "control" process is for example a process that is configured via ExecStop=
  589         and is spawned in parallel to the main daemon process in order to shut it down.
  590
  591         QueueSignalUnit() is similar to KillUnit() but may be used to enqueue a POSIX Realtime Signal (i.e.
  592         SIGRTMIN+...  and SIGRTMAX-...) to the selected process(es). Takes the same parameters as KillUnit() with one
  593         additional argument: an integer that is passed in the sival_int value accompanying the queued signal. See
  594         sigqueue(3) for details.
